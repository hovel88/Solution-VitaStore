# Матрица решений Buy vs Build vs Migrate

| Бизнес-возможность | Текущее состояние | Целевое состояние | Решение (Buy/Build/Migrate) | Обоснование |
| -- | -- | -- | -- | -- |
| POS (касса) | Толстый клиент, привязан к железу | Тонкий клиент | **Buy (SaaS)** | Стандартная функция. Разработка своего POS требует сертификации ФНС, что дорого и долго |
| Печать ценников | Локальное приложение | Облачный сервис печати | **Buy (SaaS)** | Простая функция, не особенность |
| Программа лояльности | Тетрадки, локально | Централизованная | **Build (In-house или PaaS)** | Конкурентное преимущество, но разрабатывать полностью у себя может быть дорого, вероятно проще использовать облачную инфраструктуру и управляемые базы (Redis + PostgreSQL) |
| Promo Engine | On-premise в HQ | Cloud-native | **Migrate (PaaS)** | Уникальный для компании алгоритм, но инфраструктуру надо перенести в облако |
| Smart Fulfillment | On-premise в HQ | Cloud-native | **Build (In-house) + Migrate (IaaS)** | Логика это конкурентное преимущество, но инфраструктуру вероятно лучше передать в облако или использовать Managed K8s |
| Click & Collect | Есть в HQ | Развивать | **Build (In-house)** | Конкурентное преимущество, в core бизнес-модели |
| SAP ERP | On-premise в HQ | Облачный SAP | **Migrate (IaaS, SaaS)** | Стандартная функция. Лучше воспользоваться готовым сервисом SAP ERP + HR, но если очень дорого, можно просто разместить SAP в IaaS вместо On-premise |
| Инкассация | Локальный процесс | Электронная инкассация | **Buy (SaaS)** | Не core функция, можно делать интеграцию с банками через API |
| Локальные сервера | Windows + SQL на 500 серверах | Отказ | **Migrate (IaaS, PaaS)** | Нет смысла держать on-premise, уменьшаем расходы |
| Администрирование | Свои инженеры | Облачные Managed Services | **Buy (SaaS)** | Не core-функция, вместо того чтобы растить своих SRE, проще передать эти обязанности провайдеру услуг |
| SKU Matching | VLOOKUP скрипт и ручной маппинг, 2 недели на магазин | ML-автоматизация | **Buy (SaaS) + Build (ML)** | Можно взять готовый ML-сервис на платформе и доработать слой кастомизации под свою специфику товаров |
| Мастер-данные (MDM) | Нет централизованного управления | Создать Master Data Management | **Buy (SaaS)** | Стандартный функционал |
| BI и аналитика | Разрозненные отчеты и таблички | Единая аналитика | **Buy (SaaS) + Build (In-house) + Migrate (IaaS)** | Может стать Data-driven преимуществом. Есть готовые BI-инструменты (Buy), но нужен DWH (на облачной инфраструктуре БД) и кастомные модели (Build) |
| Платежный терминал | Разные драйверы, 3 недели на новый драйвер | Универсальный шлюз | **Buy (SaaS)** | Не нужно изобретать, есть инструменты платежных шлюзов |
| Service Desk | Jira Service Management | Jira Service Management + AI | **Buy (SaaS)** | Стандартное решение, но можно добавить агентов для облегчения нагрузки |
| Безопасность | Разрозненно | Централизованно | **Build (In-house) + Buy (Cloud Security)** | Критично для бизнеса. Но полный In-house нереалистичен для 500 магазинов. Однако по соображениям безопасности нужно делать свой core SOC (Build), и совместить с облачными инструментами (WAF, DDoS, SIEM) |
